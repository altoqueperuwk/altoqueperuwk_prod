# INDICE BACKEND IMPLEMENTACION

## Objetivo

Esta carpeta separa el backend compacto por responsabilidad para que sea mas facil:

- ubicar una tabla o funcion;
- modificar un dominio puntual;
- revisar cambios sin navegar un archivo demasiado grande.

## Archivo monolitico actual

El archivo original consolidado sigue siendo:

- `3.ddl_tablas_funciones_compactas.sql`

Ese archivo hoy funciona como snapshot completo del backend compacto.

## Regla de seguridad de funciones

Todas las funciones publicas que consumira el frontend deben declararse con:

- `SECURITY DEFINER`

Esto aplica tambien a:

- funciones `GET`
- funciones `POST`
- funciones `PATCH`

La razon es evitar problemas de permisos al ser consumidas desde Supabase.

## Regla recomendada de trabajo

Si el cambio es puntual:

1. ubicar primero el dominio correcto en estos archivos separados;
2. editar el archivo puntual;
3. luego reflejar el cambio en el consolidado final si el flujo de entrega sigue usando `3.ddl_tablas_funciones_compactas.sql`.

## Uso recomendado

### Para lectura y analisis

Usar directamente los archivos separados.

### Para handoff o compilacion total

Usar:

- `3.ddl_tablas_funciones_compactas.sql`

salvo que despues decidas que la compilacion tambien se hara por partes.
